How I would build Meridian Energy Infrastructure with AI

The tools, the rules and the loop I would use to build the developer’s site, its three flows, its Website sales bot and its two agents, one small branch at a time, so that “An energy advisor will confirm a drone survey window within one business day”, “a contracted 48-hour response on any production fault” and “If the asset underperforms the model, we write the cheque” mean exactly what the site says. No step ever tells a client to touch equipment, and no step decides a payment. Meridian Energy Infrastructure is a fictional commercial solar and storage developer, and every figure here is illustrative.

I make the calls and the AI does the typing. An energy advisor approves every first email Claude drafts for a prospect’s inbox, and the asset manager approves every report note before the report reaches a client. No flow, bot or agent tells a client to touch, reset or isolate equipment: emergencies go to 911 and the utility, and the duty lead dispatches every technician by phone. No step works out, proposes or promises a payment under the production guarantee: the asset manager decides it, by hand.

Set up once, then loop, then ship

The whole framework for Meridian Energy Infrastructure in three lines.

    Set up once

    A rules file for the developer (CLAUDE.md) with the electrical safety rule and the guarantee rule at the top, the build plan, test visitors, test assets and test months with made-up figures, before the first task.

  • 2

    Build in small loops

    Frame, build, check, fold back. One branch of one flow, or one section of the site, per run, until its test row passes.

  • 3

    Ship on a yes

    Nothing is published or switched on until I approve it, and nothing goes live until the duty leads and the asset managers sign off the safety and money rows. TWO JOBS

Who does what

The split that keeps every equipment step, every site’s number and every payment a person’s.

Me

  • Decide what each flow promises a client
  • Approve every change before it goes live
  • Walk each branch with test visitors and test assets
  • Turn every mistake into a rule

The AI

  • Read the developer’s facts and the files that matter
  • Write the page, the flow and its tests
  • Run each test row and grade itself
  • Report back with the diff and the run log

When the AI starts estimating what a visitor’s roof would save, or I start placing boilerplate steps by hand, the loop is broken.

THE TOOLS

Four tools, one job each

Three to build the developer’s system, and one that works inside its scoring step, its bot and its agents.

  • 01

    Claude Code

    The builder. The developer’s pages, the Make blueprints, the n8n workflows and a step list for each Zapier Zap, drafted from the build plan with a test for each branch.

    Opus to plan, Sonnet to build
  • 02

    VS Code

    The editor. Where I read every diff, every template and every prompt Claude will run inside ME-01’s scoring step, the bot and the agents, and take over when precision beats speed.

    Human in the loop
  • 03

    Codex

    The second opinion. A fresh model reads each diff and each flow export for what the author missed, like a field mapped into the wrong place or a template that could name a payment.

    Review pass, not a build pass
  • 04

    Claude

    The model inside ME-01, the bot and the two agents. It scores each survey request for the advisors, answers visitors from the site’s published figures, drafts a first email for an advisor’s yes and drafts each report’s note for the asset manager.

    Sonnet inside the flow, bot and agents
THE RULES

Four rules I do not break

They are what keep an energy developer’s flows away from its equipment and its cheques, which belong to people.

  • R1

    Write the spec first

    If I cannot say in a paragraph what a flow promises a client, what it may read, who says yes, and that it never touches equipment or a payment, the agent will not find it in a thousand tokens. The build plan is that paragraph.

    Spec before prompt
  • R2

    Every write is approval-gated

    Agents draft. Nothing reaches the developer’s live site or a switched-on flow unreviewed. An energy advisor approves every first email Claude drafts for a prospect’s inbox, and the asset manager approves every report note before the report reaches a client.

    No autonomous writes
  • R3

    One branch at a time

    One branch, one test row, one context. A fresh session per branch beats one long session for all three flows.

    Reset early, reset often
  • R4

    The test row grades it

    Each branch goes in with its row from the build plan’s test matrix, and is run against it before I look, including the request with no score, the organisation that tries to instruct Claude and the morning with nothing due.

    Self-review built in
THE LOOP

Frame, build, check, fold back

Four steps, repeated for every branch until its test row passes. Click any step or pin.

A WORKED EXAMPLE

ME-01, from Book the site survey to live

The developer’s site survey flow, taken through the loop.

  1. 1Frame

    Read the site: Request a Site Assessment opens a wizard of four questions, the kind of facility, the area and monthly spend, the location and the structure, then a preliminary model and Book the site survey, whose confirmation says “An energy advisor will confirm a drone survey window within one business day.” The minimum site is 80,000 sq ft or 250 kW, and the survey promises “a measured number, not a sales estimate.” The tempting build has Claude write the visitor’s email, with its score and a savings estimate, and books any high score straight into the calendar. Both are wrong for this developer: the number comes from the survey, and a person confirms the window.

  2. 2Frame

    So in ME-01 Claude only scores, from the area, the spend and the location, and the score only routes: it goes to the pipeline sheet and the energy advisors, never to the visitor. Both emails are fixed templates that never call the assessment free or quote a figure, and Cal.com’s Drone site survey event waits for an advisor to confirm. Done means every request is logged, scored and in front of the advisors within minutes, and answered by a person within one business day. Then I wrote ME-01’s spec and its ten test rows, among them a request with no score, an organisation that tries to instruct Claude and a morning with nothing due.

  3. 3Build

    Built one branch per session, test first: the custom webhook, Score the site and Read the score with their error routes, Log the site with its Confirm by, Tell the advisors, the Router with Not yet as its fallback route, the booking email and the five savings guides, then the due scenario, with its Make an API call on the Due tab.

  4. 4Check

    Ran each row with test visitors. The Nothing due row failed: on a morning with nothing due, the advisors still got a reminder with one empty line, because the Due tab’s FILTER showed #N/A, which the API returned as a row. Then a fresh reviewer model read the scenario’s blueprint and saw that Score the site was mapped the whole webhook bundle, so Claude received the name, the organisation and the email after all. No row that checked only the score could show it.

  5. 5Fold back

    Each fix went in behind a check that failed first: the Due tab’s FILTER now sits inside IFERROR with an empty result, so a quiet morning leaves the tab empty and the filter stops on the length of its values; and Score the site maps only the facility, the area, the spend and the location, with t06 now checking Claude’s input. Two rules went into CLAUDE.md: a sheet a scenario reads is empty when there is nothing, never an error value; and a Claude step gets named fields, never the whole bundle.

  6. 6Ship

    I approved it, the energy advisors read Claude’s scoring instructions and the two templates, t10 was signed off in the safety and guarantee review, and I turned both scenarios on. I pressed Request a Site Assessment on the developer’s real site with a test warehouse, and watched the row land with its score, the advisors’ group hear of it, the booking email reach the test inbox with the reference and no score, and Cal.com hold the window for an advisor to confirm.

HABITS

What I do every time

Small, boring, and the reason the developer’s flows keep working.

  • 1

    Fresh session per branch

    A long chat drifts. Each branch starts clean, with its spec and its test row.

  • 2

    Read every diff and prompt

    Every change, every template and every prompt Claude will run inside ME-01, the bot and the agents is read before it goes anywhere, so nothing can tell a client to touch equipment or name a payment.

  • 3

    Test visitors, never real ones

    Every branch is walked with made-up test visitors, test assets and test months before a real firm or client meets it.

  • 4

    Check it on the live site

    Tests passing is not the end. I press Request a Site Assessment on the developer’s real site, answer the four questions, and follow them.

Done is a survey request in front of an energy advisor within minutes of Book the site survey, not a diff.

PLAIN ENGLISH

Every term on this page, in one line

Plain English for the technical words above.

Claude Code
Anthropic’s AI coding tool. It works in the terminal, on real files.
VS Code
Visual Studio Code, the code editor where I read what was written and edit by hand.
Codex
OpenAI’s coding agent, used here to review work it did not write.
Claude
Anthropic’s AI model inside ME-01’s scoring step, the bot and the two agents once they ship. Claude Code is what builds them.
Opus
Claude’s most capable model, used for planning.
Sonnet
Claude’s faster model, used for most of the building and inside the flow, the bot and the agents.
Make
The automation tool ME-01 runs in. A scenario can be imported as a blueprint.
Blueprint
A Make scenario saved as a file, so it can be drafted, read and imported.
Router
Make’s way of splitting a scenario into routes. Its fallback route takes whatever no other route does.
Fallback route
The Router’s route for a score below 7, or no score at all: the savings guide.
Make an API call
A Make module that calls the Google Sheets API directly, here to read the Due tab.
Webhook
The address the wizard posts its answers to, which starts the scenario.
n8n
The automation tool ME-02, the bot and the agents run in. A workflow can be written as a file and imported.
Zapier
The automation tool ME-03 runs in. Each Zap is built by hand from its step list.
Cal.com
Where a strong site books its drone survey window, for an energy advisor to confirm.
Wizard
The site’s four questions behind Request a Site Assessment.
Due tab
A tab of the pipeline sheet listing the requests still owed an advisor’s answer.
Safety and money rows
The test rows that prove no template tells a client to touch equipment or names a payment, signed off before go-live.
Spec
A short written description of what done looks like, agreed before any code.
Context
Everything the AI can see while it works. Less is better.
Branch
One path through a flow, like the request with no score, built and tested on its own.
Test row
One line of the test matrix: an input, the branch it takes and what must happen.
Test matrix
Every test row for every flow, in the build plan, ticked as each one passes.
Test visitors
Made-up visitors with made-up sites, so a branch can run without touching a real one.
Diff
The exact lines a change adds and removes.
Second opinion
A different model reading the work, to catch what the author missed.
Approval gate
A point where the work stops until a person says yes. An energy advisor approves every first email Claude drafts for a prospect’s inbox, and the asset manager approves every report note before the report reaches a client.
CLAUDE.md
The rules file Claude Code reads at the start of every session.
Loop-back
A cable that sends the work back to an earlier step.
Fold back
Turning a mistake into a rule or a test row, so it does not happen again.
Fresh session
A new, empty AI chat, started clean for the next branch.
Test first
Writing the test before the code, and watching it fail first.
Reviewer model
A fresh AI model asked only to review finished work.
